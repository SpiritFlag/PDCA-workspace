## 1. Overview

### 1.1 목적

사이클 종료 시 PDCA 문서를 워크스페이스 서버에 반영하는 작업에서 **두 가지 누수**를 닫는다.

1. **토큰 누수** — 클로드가 MCP `document_write`를 직접 호출하려면 문서 본문 전체를 출력
   토큰으로 재생성해야 한다. 4종 합계가 수만 토큰이고, 그 과정에서 원본과 한 글자라도
   달라지면 서버 사본이 디스크 원본과 갈라진다.
2. **대상 누수** — 절차가 "이번 사이클 4종"만 상정한다. 이전 사이클 문서를 고쳐도 그 사실을
   사람이 기억해서 따로 올려야 하고, 실제로 기억되지 않았다(F65).

두 누수의 해법이 같다: **파일을 그대로 읽어 보내는 스크립트**에 **git이 정한 대상 목록**을
물린다.

### 1.2 배경

이 사이클은 6차(`expand-mcp-agency`)가 남긴 두 갈래가 만나는 지점에 있다.

**갈래 ①** — 6차 종료 시점에 RULE.md 종료 절차가 "PDCA-workspace MCP로 릴리즈 생성"을
요구했으나 `cycle_create` MCP 툴이 존재하지 않았다(D-46이 "한 사이클에 경계는 하나만
옮긴다"는 원칙으로 쓰기 툴을 0건으로 유지했기 때문). 6차는 릴리즈를 브라우저로 만들고
**툴 신설을 다음 사이클(=이번)로 재이월**했다. 이번 사이클은 그 재이월 항목에 대해
**"MCP 툴을 만들지 않는다"**로 답한다(D-54, §1.4 6T-2 참조) — 클로드가 실제로 호출하는
것은 스크립트이지 MCP 툴이 아니므로, 툴을 만들어도 소비자가 없다.

**갈래 ②** — 6차 회고 6.2가 "RULE.md가 세션 밖에서 바뀌는 걸 사전에 감지할 방법이 없었다"를
Problem으로 올리고 Try 4로 "Plan 착수 루틴에 RULE.md 변경 확인을 넣자"를 제안했다. 이번
사이클은 **RULE.md를 직접 개정하는 사이클**이라 그 제안이 곧바로 시험대에 오른다.

그리고 이 사이클의 직접 방아쇠는 형의 지적이다 — *"가끔 이전 사이클 문서도 수정하는데, 그걸
내가 수동으로 트래킹할 수 없어서 이 스크립트를 만드는 것"*. 이 한 문장이 스코프를
"4종 업로더"에서 "변경분 동기화기"로 넓혔고, S2·S3가 거기서 나왔다.

| **6T-3** | Design Decision Record에 **"파생 효과" 열**을 추가해볼 것 | **Design 단계에서 시도.** 이번 사이클은 파생 효과가 특히 잘 보이는 구조다 — D-55(git 기반 탐지)가 D-56(역파서 필요)을 **직접 낳고**, D-56이 스코프를 "신규 1파일"에서 "신규 1 + `src/` 수정 1"로 넓혔다. 이 연쇄를 Design 표의 열로 명시한다 |
| **6T-4** | RULE.md 변경 감지를 Plan 착수 루틴에 넣을 것 | **이행함.** 이번 Plan은 착수 시 `docs/RULE.md`를 전문 확인하고 시작했으며, 종료 절차 3·4번의 현재 문구를 F-실측이 아니라 **개정 대상**으로 §2.1 S6에 올렸다. 6차가 "감지 못 해서 뒤늦게 고쳤다"고 적은 그 파일을, 이번엔 **의도적으로 고치는 쪽**에 서 있다 |

## 2. Scope

### 2.1 In Scope — 6건 고정 (확장 금지)

- [ ] **S1 — `scripts/docs-upload.ts` 신설.** 파일을 `readFile`로 읽어 HTTP로 전송한다.
      본문이 LLM 컨텍스트를 통과하지 않는 것이 이 파일의 존재 이유다. `package.json`에
      `docs:upload` 스크립트 1줄 추가(기존 `dev:api`·`test:l1`의 `.env.local` 주입 패턴 따름).
- [ ] **S2 — git 기반 대상 선정.** 최신 태그 이후 변경된 `docs/PDCA` 문서를 탐지한다
      (작업트리 미커밋분 ∪ `최신태그..HEAD` 커밋분). `--cycle <이름>` 필터와 `--all`
      탈출구를 함께 제공한다.
- [ ] **S3 — 경로 역파서 신설.** `src/features/cycle/lib/cyclePath.ts`에 경로 →
      `(yearMonth, name, stage)` 파서를 추가한다. 빌더와 같은 파일에 두어 왕복 정합을
      구조적으로 보장한다(I-3 교훈 — 하드코딩 사본을 만들지 않는다).
- [ ] **S4 — 사이클(릴리즈) 생성 통합.** `--version` 지정 시 REST `POST /cycles`로 생성하며
      **문서 업로드보다 먼저** 실행한다. 이미 존재하면 생략한다.
- [ ] **S5 — tsc 커버리지.** `tsconfig.server.json`의 `include`에 `"scripts"`를 추가해
      `tsc -b`가 신규 스크립트를 타입체크하게 한다(F64 사각지대 해소).
- [ ] **S6 — RULE.md 종료 절차 개정.** 3·4번(MCP 릴리즈 생성 / MCP docs 반영)을 스크립트
      한 단계로 통합하고, **MCP `document_write` 직접 호출을 금지하는 문구**를 명시한다.

|----|------|------|------|
| **D-53** | 문서 업로드는 **MCP `document_write` 경유** | REST 3왕복(POST→by-path→PATCH) | F55·F56 — upsert가 서버에 이미 있고 MCP에만 노출돼 있다. REST로 구현하면 같은 로직의 사본이 늘고 왕복이 3배가 된다. 서버 무수정 제약 하의 유일한 합리적 선택 |
