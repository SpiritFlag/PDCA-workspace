## Executive Summary

| 항목 | 내용 |
|------|------|
| 기능 | 버전(release)·릴리즈노트 관리 + PDCA 사이클 문서 진입로 + 임포트 폼 사이클 중심 재설계 + 전역 계층 사이드바 + 여름 테마 + 로컬 상주 개발 서버 |

> 만들어진 물건은 좋고, 만든 방식이 0점이다.

### 1.3 실현된 가치

| 관점 | 내용 |
|------|------|
| **Problem** | 문서·백로그는 1급 데이터가 됐는데 릴리즈만 아니었다. 사이클을 묶는 건 경로 컨벤션(사람의 약속)뿐이었고, 릴리즈노트는 report.md에 묻힌 채 git tag와 어긋났다(2차 report `v0.2.0` vs 실제 태그 `v0.1.1`) |
| **Solution** | `cycles` 테이블로 **버전을 1급 엔티티**로 세웠다. `version`이 유일키, 릴리즈노트는 마크다운 컬럼, PDCA 사이클(`name`+`yearMonth`)은 **선택 연결**. 사이클이 붙은 버전 카드는 plan/design/analysis/report 4버튼으로 문서를 오가고, 없는 단계는 경로가 프리필된 생성 폼을 연다 |
| **Function/UX Effect** | 프로젝트 개요에 버전 목록(정렬 3종)이 생겼고, 사이드바가 프로젝트 진입 없이도 워크스페이스>프로젝트>백로그·버전·문서 전역 트리로 열린다. 문서 임포트에서 경로를 한 글자도 안 친다. 로컬 API 응답이 요청당 ~2초에서 수백 ms로 떨어졌다 |
| **Core Value** | **"PDCA 산출물의 단위는 문서가 아니라 릴리즈다."** RULE.md의 경로 컨벤션을 DB 레코드와 유일 제약으로 승격시켜, 앱이 "v0.1.2가 무엇이었는가"를 스스로 대답하게 만들었다 |

### 6.1 잘된 것 (Keep)

- **좋은 구조는 절차 없이도 지켜졌다.** 라우트→서비스→scoped 3층, ownerId 2단 조인, 에러 코드 6종 — 설계 문서 한 장 없이 짰는데 6/6, 9/9로 만점이다. 2차에서 세운 구조가 "따라가는 게 벗어나는 것보다 쉬운" 수준으로 명확했다는 뜻이다. **구조로 강제한 것은 안 무너진다.**
- **토큰 이름을 계약으로 지킨 덕에 테마 전면 교체가 CSS 1파일 + 상수 1줄로 끝났다.** 1차 §5.5의 "색은 변수로만" 규약이 1년치 이자를 한 번에 지급한 순간. 규약을 깨야 할 때도(D-25) **깰 것과 지킬 것을 분리**해서 깼다.
- **틀리기 쉬운 곳을 정확히 골라 테스트했다.** 순수 함수 3개 중 `versionSort`만 테스트했는데, 그게 바로 `v0.1.10 < v0.1.2` 함정이 있는 유일한 자리다. 커버리지 숫자가 아니라 위험을 보고 고른 선택.
- **모델을 도중에 뒤집는 판단 자체는 옳았다.** `0002`(사이클 우선) → `0003`(버전 우선)은 "핫픽스처럼 사이클 없는 릴리즈가 있다"는 현실을 만난 결과다. 늦게라도 바꾼 게 맞다.

### 6.2 개선이 필요한 것 (Problem)

- **회고가 저장은 됐는데 재생되지 않았다.** 2차 Try 3건이 0/3 적용이다. 특히 D1("`.nullable()` 여부를 명시적으로 결정")은 2차에서 Critical로 잡고, 회고에 적고, 이월까지 시킨 항목인데 **3차에서 다른 컬럼에 같은 버그를 만들었다.** 회고는 Plan/Design 단계에서 소비되는데, 그 단계가 없으면 회고는 읽히지 않는 파일이 된다.
- **확립한 검증 자산을 유휴로 뒀다.** 2차의 `app.request()` 실 DB 하네스는 정렬 SQL 캐스팅 버그를 잡아낸 실적이 있는 도구다. 이번엔 0회 사용했고, 그 결과 C-1·I-1을 **코드 정독으로만** 발견했다. 둘 다 design §8.2 시나리오 #10·#5에 정확히 대응한다 — 하네스만 돌렸으면 공짜로 잡혔다.
- **단일 원천을 만들어놓고 도메인 밖에서 안 썼다.** `cyclePath.ts`·`yearMonth.ts`를 D-22로 명시까지 해놓고, 정작 `ImportDialog`에서 셋 다 우회했다. **2차 회고 Problem #2("단일 원천을 서비스 계층까지만 적용하고 검증 계층까지 못 미침")와 같은 형태의 재발**이다 — 원천을 만드는 것과 강제하는 것은 다른 일이다.
- **모델 이름을 뒤집힌 의미에 맞추지 않았다.** `cycles` 테이블의 1급 키가 `version`이 된 순간 이름은 `releases`였어야 한다. UI만 "버전"으로 고치고 코드는 그대로 둬서, **화면과 코드가 다른 단어를 쓰는 상태**를 남겼다.
- **커밋 1개(`a78f188`)에 24파일을 담았다.** 리뷰 단위로 과대하고, 나중에 이 사이클을 되짚을 때 "임포트 폼 재설계"와 "버전 도메인 추가"가 한 덩어리로 붙어 있어 분리가 안 된다.

### 6.3 다음에 시도할 것 (Try)

- **[P-1] 새 Plan 문서에 "직전 사이클 Try 이행 현황" 표를 필수 섹션으로 둔다.** 항목별로 ✅/❌/N/A를 적고, ❌면 이번 사이클에서 왜 안 하는지 한 줄. 이번 사이클이 0/3을 낸 이유는 그 표가 없어서 **Try가 어디에서도 다시 읽히지 않았기** 때문이다.
- **[P-2] zod 필드 정의 시 Design 표에 "지울 수 있는가" 열을 필수로 둔다.** 2차 Try D1을 권고에서 **표 형식**으로 승격. 형식이 없는 권고는 두 사이클 연속 무시됐다.
- **[P-3] Design §8 Test Plan의 L1 시나리오를 DoD 체크박스로 옮긴다.** 기준을 "작성"이 아니라 **"실행"**으로. `app.request()` 하네스는 2차에 이미 있으므로 추가 비용은 시나리오 작성뿐이다.
- **[P-4] 도메인 순수 함수를 만들면 같은 커밋 안에서 호출부를 grep으로 전수 확인한다.** `cycleStagePath`를 만든 커밋에 하드코딩 경로가 함께 들어간 건, 만든 직후 검색 한 번이면 잡혔을 일이다.
- **[P-5] 릴리즈 버전 표기의 단일 원천을 `cycles.version`으로 정한다.** 지금 git tag·report §9 Changelog·`cycles` 레코드 세 곳에 버전이 따로 존재하고, 2차에서 실제로 어긋났다(report `v0.2.0` vs tag `v0.1.1`). **이 사이클이 만든 기능이 이 문제의 해법**이므로, 다음 사이클부터 report §9를 `cycles.release_note`에서 생성하는 걸 검토한다.

### 6.4 PDCA를 건너뛴 것에 대하여

건너뛴 대가는 **6가지 형태로 코드에 남았다**([analysis](./cycle-release-note.analysis.md) §5):
학습 미재생(C-1 재발), 마이그레이션 화석(`0002`→`0003`), 검증 자산 유휴(0/11),
소비자 누락(MCP 0툴), 단일 원천 누수(I-3), 의도 없는 교환(I-5 제목 고정).

동시에 **건너뛰어도 안 무너진 것**이 있었다: 계층 구조, 보안, 회귀 안전.
공통점은 셋 다 **코드 구조나 자동 검사가 강제**한다는 점이다.

> **그래서 결론은 "항상 PDCA를 다 돌려라"가 아니다.**
> PDCA가 실제로 붙잡고 있던 건 **구조가 강제하지 못하는 것들** — 회고의 재생, 검증의 실행, 소비자 목록, 스코프의 명시 — 이었다.
> 절차를 줄이려면 그 4가지를 **다른 수단으로 강제**해야 한다(P-1~P-3이 그 시도다).
> 절차 없이도 지켜지는 것까지 절차로 반복하는 건 낭비고, 절차만 지키던 것을 절차 없이 두는 건 이번 결과다.
